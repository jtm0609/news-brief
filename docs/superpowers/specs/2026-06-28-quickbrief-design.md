# QuickBrief — 핵심만 빠르게 읽는 뉴스/정보 웹 서비스 (설계 문서)

- 작성일: 2026-06-28
- 단계: 1차 — 더미 데이터 기반 UI/UX 구현 (데이터 연동은 후속 단계)

## 1. 목적과 배경

출퇴근 등 짧은 시간에 뉴스·정보를 **핵심만 빠르게 파악**하도록 돕는 웹 서비스.
일반 뉴스는 본문이 길어 한눈에 파악하기 어렵다. 이 서비스는:

1. 카테고리별 섹션으로 글을 보여주고,
2. 사용자가 고른 글의 **핵심 요약**을 먼저 보여주며,
3. 더 알고 싶으면 같은 글 안에서 **전체 본문**으로 펼쳐 볼 수 있게 한다.

## 2. 범위

### 이번 범위 (1차)
- 순수 HTML/CSS/JavaScript (빌드 도구·Node 불필요). 브라우저로 파일을 직접 열어 동작.
- 더미 데이터로 메인 화면 + 상세 화면 완성.
- 메인: 카테고리별 세로 스크롤 섹션 + 반응형 카드 그리드(PC 2~3열 → 폰 1열).
- 상세: 상단 핵심 요약 → "자세히 보기"로 전체 본문 펼침.

### 제외 (YAGNI)
- 로그인 / 개인화 (관심사 저장 없음).
- 실제 RSS / 뉴스 API / AI 요약 연동 (후속 단계).
- 검색 기능 동작 (헤더에 아이콘 자리만, 동작 없음).
- 더보기 / 페이지네이션 / 다크모드.

### 후속 단계 (설계만 고려, 이번 구현 아님)
- `api.js`의 데이터 공급 함수 내부를 실제 RSS/AI 호출로 교체.
- 추후 React + Vite로 렌더링 계층만 이전 (데이터·구조는 재사용).

## 3. 기술 접근

**순수 HTML/CSS/Vanilla JS, 빌드 없음.** 선정 이유:
- 현재 환경에 Node.js가 없고, 더미 UI 단계엔 빌드 도구가 과함.
- 브라우저로 즉시 실행/확인 가능.

**나중에 React로 전환하기 쉽게 하는 설계 원칙:**
- **데이터 분리**: 모든 글 데이터를 `data.js` 한 곳에 모음.
- **데이터 공급 격리**: 데이터 접근은 `api.js`의 `getArticles()`, `getArticleById()`만 통해서. 향후 RSS/AI/React 전환 시 이 파일만 교체.
- **화면을 조각 단위로**: 카테고리 섹션 / 카드 / 상세를 각각 함수로 분리 → React 컴포넌트와 1:1 대응.
- **의미 기반 CSS 클래스**: 대부분 그대로 재사용 가능.

## 4. 파일 구성

```
news-brief/
├── index.html        # 메인 화면
├── article.html      # 상세 화면
├── css/
│   └── style.css     # 의미 기반 클래스, 반응형
├── js/
│   ├── data.js       # 더미 글 데이터 배열
│   ├── api.js        # getArticles(), getArticleById() — 데이터 공급 격리
│   ├── home.js       # 메인 렌더링
│   └── article.js    # 상세 렌더링
└── assets/           # 더미 썸네일 등
```

## 5. 데이터 모델

`data.js`의 글 1개 구조:

```js
{
  id: "econ-001",                 // 고유 ID (상세 페이지 식별)
  category: "경제",                // 이 값으로 섹션 자동 분류
  title: "환율 1,400원 돌파",       // 카드/상세 제목
  thumbnail: "assets/econ-001.jpg",// 썸네일 (없으면 자동 생략)
  source: "○○일보",               // 출처
  publishedAt: "2026-06-28T08:30", // 발행 시각 (표시/정렬용)
  summaryPoints: [                 // 핵심 요약 불릿 (한눈에 보는 핵심)
    "원·달러 환율이 1,400원을 넘어섬",
    "수입 물가 상승 우려 확대",
    "당국, 구두 개입 시사"
  ],
  fullBody: "기사 전체 본문 ...",    // 자세히 보기에서 펼쳐지는 원문
  sourceUrl: "https://..."         // 원문 링크 (선택)
}
```

**의도**
- `summaryPoints`(핵심)와 `fullBody`(전체)를 명확히 분리 → "핵심 먼저, 원하면 자세히"를 데이터 구조에 반영.
- `category`만 있으면 섹션이 자동 생성됨 (카테고리 목록을 따로 관리하지 않음). 카테고리는 데이터에서 동적으로 도출.

## 6. 데이터 공급 계층 (`api.js`)

```
getArticles()        → 전체 글 배열 반환 (현재: data.js 더미 반환)
getArticleById(id)   → 해당 id의 글 1개 반환 (없으면 null)
getCategories()      → 글들에서 등장하는 카테고리 목록을 순서대로 도출
```

후속 단계에서 이 함수들의 내부만 RSS/AI 호출로 바꾼다. 호출부(home.js, article.js)는 변경 없음.

## 7. 메인 화면 (`index.html` + `home.js`)

**구성 (위→아래)**
1. 상단 고정 헤더: 로고 + 검색 아이콘(자리만) + 메뉴 아이콘.
2. 카테고리 섹션들: `getCategories()` 순서대로 세로 나열. 각 섹션 = 섹션 제목 + 해당 카테고리 카드 그리드.
3. 카드: 썸네일 + 제목 + 핵심 불릿 1개 미리보기 + `자세히 →`. 카드 전체가 클릭 영역.

**반응형**: 카드 그리드는 PC 2~3열, 폰 1열로 자동 전환.

**표시 규칙**: 카테고리당 최대 6개까지 표시 (더미라 6개 이하로 채움). 카드 미리보기는 "제목 + 핵심 불릿 1개".

**흐름**
```
로드 → getArticles() → category 기준 그룹핑 → 섹션+그리드 렌더
     → 카드 클릭 → article.html?id=<id> 로 이동
```

## 8. 상세 화면 (`article.html` + `article.js`)

**구성 (위→아래)**
1. 상단 바: `← 뒤로`(메인으로) + 카테고리 뱃지.
2. 제목 영역: 큰 제목 + 출처 + 발행 시각.
3. **핵심 요약 블록**: `summaryPoints`를 강조 박스에 불릿으로. 로드 시 스크롤 없이 먼저 보이는 것이 목표.
4. `자세히 보기 ▾` 버튼.
5. 전체 본문: 기본 접힘. 버튼 클릭 시 `fullBody` 펼침. 맨 아래 `원문 보기 →`(sourceUrl, 있을 때만).

**"자세히 보기" 방식**: 같은 페이지에서 펼치기(아코디언). 페이지 이동 없이 핵심만 보거나 펼쳐 깊이 볼 수 있음.

**흐름**
```
로드 → URL 쿼리에서 id 추출 → getArticleById(id)
     → 제목 + 핵심 요약 렌더 (본문 접힘)
     → '자세히 보기' 클릭 → 전체 본문 펼침
잘못된/없는 id → "글을 찾을 수 없습니다" + 메인으로 가는 링크
```

## 9. 디자인 톤

- 밝고 깔끔한 뉴스 톤: 흰 배경 + 진한 회색 텍스트 + 카테고리별 포인트 컬러.
- 가독성 우선: 넉넉한 줄간격, 큰 제목, 핵심 요약 박스는 연한 배경으로 강조.
- 반응형: PC 2~3열 → 폰 1열.

## 10. 더미 데이터 범위

- 카테고리 4개: 경제 / IT·기술 / 사회 / 세계.
- 카테고리당 글 4~6개, 총 약 20개.
- 각 글: 제목 + 핵심 불릿 3개 + 전체 본문 2~3문단 + 더미 썸네일.

## 11. 에러 처리

- 상세 페이지에서 id가 없거나 매칭 글이 없으면: "글을 찾을 수 없습니다" 안내 + 메인 링크.
- 썸네일 파일이 없으면 카드/상세에서 이미지 영역 생략(깨진 이미지 노출 안 함).
- 빈 카테고리는 섹션 자체를 렌더링하지 않음.

## 12. 검증 (수동)

브라우저로 `index.html`을 열어 확인:
1. 카테고리 섹션과 카드 그리드가 보인다.
2. 창 폭을 줄이면 1열로 접힌다.
3. 카드를 클릭하면 상세 페이지로 이동한다.
4. 상세 페이지 상단에 핵심 요약이 먼저 보인다.
5. "자세히 보기"를 누르면 전체 본문이 펼쳐진다.
6. 잘못된 id로 접근하면 안내 메시지가 보인다.

## 13. 성공 기준

`index.html`을 여는 것만으로 위 검증 1~6이 모두 통과한다. 데이터 연동 없이도 서비스의 핵심 경험(핵심만 빠르게 → 원하면 자세히)이 완성된 형태로 동작한다.
